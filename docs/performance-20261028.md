# 2026-10-28 本地性能与安全优化

本轮保留 0.4.0 / 0.4.0-T 的界面和功能，生成本地优化候选，未推送、未发布。
源码算法基线为 `e219ced`；EXE 分别与本轮开始前的 `Onion-0.4.0-cape-names.exe`、`Onion-0.4.0-T-cape-names.exe` 比较。

## 体积

| 版本 | 原文件 | 优化候选 | 减少 |
| --- | ---: | ---: | ---: |
| 公众版 | 31,925,224 B | 23,765,342 B | 25.56% |
| THUnion | 32,109,605 B | 23,886,433 B | 25.61% |

采用 x86 BCJ + LZMA2 分组无损压缩 Qt 运行库，启动时以小块流式恢复并逐文件核验 SHA-256。
公众版 133 个、特供版 137 个延后恢复文件均与基线逐字节比较一致。
两版均保留 99 个翻译文件及原有 20 / 21 个 Qt 插件；未修改 DLL 字节及其原始安全元数据。

这是分发 EXE 的体积减少，不代表恢复后的运行库减少相同比例。
解压使用两个工作线程，LZMA 字典合计 24 MiB，另有解码和文件缓冲开销；恢复后压缩中间文件会清理。
`ONION_PACK_QT=0` 可关闭这一打包方式，用于排查启动或平台兼容问题。

## 可复现测量

Windows、Python 3.13.7、PyInstaller 6.11.1、PySide6 6.12.0。
同机、无并行构建负载，单项取 3 或 5 次的中位数；HTTPS 初始化取 10 次中位数。
测试创建临时样本，读取真实 Java 候选路径，不启动用户的 Minecraft，不使用账户令牌。
算法比较从 Git 读取对应功能模块，共享安全辅助函数使用当前实现；这不等同于回退整个程序。EXE 启动比较则直接运行两个实际构建。

| 工作负载 | 原耗时 / 内存 | 优化后 | 减少 |
| --- | ---: | ---: | ---: |
| 6000 个资源文件存在及大小检查 | 904.057 ms | 43.974 ms | 95.14% |
| 200 个模组重复读取元数据 | 36.225 ms | 1.866 ms | 94.85% |
| 200 个模组元数据与图标读取 | 95.780 ms | 26.628 ms | 72.20% |
| 200 个模组更新查询，模拟每次请求 10 ms | 595.040 ms | 82.402 ms | 86.15% |
| 28 MiB 文件同时检查 SHA-1、SHA-256 | 29.938 ms | 24.272 ms | 18.92% |
| 回环 HTTP 下载 28 MiB 并验证双摘要 | 120.967 ms | 69.071 ms | 42.90% |
| 10000 个任务的调度额外内存峰值 | 17,427,465 B | 135,085 B | 99.22% |
| 重复准备 12 MiB 原生库 | 101.550 ms | 13.119 ms | 87.08% |
| Java 候选路径发现，结果均为 8 条 | 5250.134 ms | 562.863 ms | 89.28% |
| 重复建立 HTTPS 请求处理器 | 18.396 ms | 0.128 ms | 99.30% |

上述模组查询由 400 次请求降为 2 次，使用官方批量接口，每批最多 200 个摘要。
请求耗时来自模拟服务延迟，不代表真实互联网下载提速；回环 HTTP 也不代表公网带宽。
模组列表指标只包含文件、元数据和图标读取，不包含 Qt 绘制。
下载内存指标只包含额外调度分配，不包含已存在的任务列表、正文缓冲和整个进程。
文件改写受缓存和系统扫描影响较大。例如此前多轮原生库基线约 31–102 ms、优化后约 13–20 ms；确定减少了重复解压写入，表中耗时百分比仅代表最后一轮测量。

## 启动代价与测量边界

两版各做 5 轮交替运行的真实入口启动自检。测量包含 EXE 解包、Qt 初始化、自检和退出，**不是首帧显示时间**。

| 版本 | 基线中位数 | 优化候选中位数 | 差值 |
| --- | ---: | ---: | ---: |
| 公众版 | 1.847 s | 2.047 s | +0.200 s |
| THUnion | 2.034 s | 2.103 s | +0.070 s |

体积目标已达到，部分检查和准备步骤耗时减少超过 50%。启动自检有小幅解压开销。
尚未证明完整 Minecraft 启动或真实公网下载普遍提速 50%；它们受游戏、Java、磁盘、杀毒、代理及远端服务影响。
没有用较快的偶发样本或模拟请求替代这一结论。

## 算法与边界

- 资源存在检查按哈希前缀目录使用 `scandir`，合并重复对象；仍核对大小。对可执行代码不引入仅凭时间戳信任的摘要缓存。
- 模组展示摘要最多 1024 项 / 估算 8 MiB，图标最多 512 项 / 估算 16 MiB；替换或修改文件后失效。依赖审计和安装事务继续做自己的核验。
- 下载队列只保持与工作线程数成比例的 Future；结果和输入任务仍占 O(n) 空间。正文流式更新双摘要，减少落盘后重读。
- Java 发现利用目录条目属性，减少不存在路径的探测，保留深度、数量、取消和循环链接边界。
- 原生库重复准备校验来源 JAR 及目标文件摘要后复用；源或目标变化重新提取，摘要记录最多 1024 项。
- TLS 仅复用验证配置，最长五分钟后刷新；保持证书和主机名验证。代理路径、连接和账户凭据不由此缓存。

## 本轮安全修正

- ZIP 解压另外检查实际内容长度与声明长度一致，拒绝 CRC 正确但长度不符的截短条目。
- 下载、解压、账户及配置文件最终落盘复用有限重试的原子替换；整合包目录发布仅对短暂 Windows 占用错误有限重试，并响应取消。
- 续传检查起点、结尾、总长及声明长度，拒绝错误的 Range 和截断响应。
- 下载执行文件大小上限，资源索引限定 32 MiB；损坏的缓存索引强制重新获取并验证，失败明确报错。
- 模组批量查询失败明确报错，不当作“没有更新”。
- 元数据、图标、日志单行和诊断文件读取有界；超大诊断保留头 3 MiB 和尾 1 MiB，中间标记省略，可能需要用户另行查看完整原日志。
- 启动器日志、游戏输出和诊断导出统一尽力隐藏令牌、密码、API key、代理凭据等；发布日志前仍需人工复核。
- Windows 旧配置密钥迁移使用带有限重试的原子替换。保存失败不再被迁移流程静默忽略；保留旧文件并报错。
- 压缩库先验证清单路径、大小及每文件 SHA-256，再进入 Qt 加载；损坏载荷、路径越界均有回归覆盖。

## 验证

- 公众版 324 / 324，THUnion 330 / 330 全部通过。
- Windows 旧明文测试密钥连续 25 次隔离迁移成功；最终源码 330 次重复故障、完整性、取消和缓存失效检查通过。测试 ZIP 固定时间戳，避免二秒时间粒度导致字节比较偶发失败。
- 两版真实 EXE 均通过实际入口、冻结 UI、Windows 栅格绘制和打包依赖检查；THUnion 另通过原生 Web 检查。
- 用两个真实 EXE 的临时副本分别完成自动替换重启，目标含中文、方括号、单引号及自定义文件名；文件名、路径、测试设置和 SHA-256 均保持正确。
- 更新测试显式构造已失效的 PyInstaller 继承环境，验证新进程创建独立运行时。

这些结果不构成“已发现全部漏洞”的保证。测试和构建产物均保留在本地，账户及游戏数据未上传。
