## 2. 核心结论

美西螈的平滑感来自正确的状态边界和稳定布局，动效曲线只是其中一环。

1. 页面、页面内部参数、局部控件、异步结果不是同一种变化；它们不会共用一个“每次操作整页动一下”的包装器。
2. 页头、侧栏、页面背景和滚动容器具有稳定的层级；页面过渡层明确避免 `transform`。
3. 导航的明显流动感来自文字背后的胶囊，前后边缘错时移动形成拉伸和回收；并非把正文整体推一下。
4. 首次布局、窗口尺寸变化、数据加载后的布局变化，通常直接校准终态；不能把布局纠正误当作用户触发的动画。
5. 异步任务、组件生命周期和动画生命周期分离；数据回来不会再自动重播整页过渡。
6. 当前 Onion 的 18px 整页平移与这些规则相反。坐标单调变化的测试只能证明“动了”，不能证明目标正确或视觉平滑。

## 3. 美西螈的具体算法与流程

### 3.1 页面切换：路由键决定是否发生过渡

证据：[App.vue:239](https://github.com/Mystic-Stars/Axolotl/blob/cf17974612cd6dcab139416e0bc5fbea252ce499/apps/app-frontend/src/App.vue#L239)、[App.vue:3098](https://github.com/Mystic-Stars/Axolotl/blob/cf17974612cd6dcab139416e0bc5fbea252ce499/apps/app-frontend/src/App.vue#L3098)、[global.scss:754](https://github.com/Mystic-Stars/Axolotl/blob/cf17974612cd6dcab139416e0bc5fbea252ce499/apps/app-frontend/src/assets/stylesheets/global.scss#L754)。

源码事实：

1. 路由导航提交后，`RouterView` 给出目的组件和目的路由。
2. `getPageTransitionKey()` 先检查路由元数据 `pageTransitionGroup`。
3. 没有分组时使用完整路由；有实体 ID 时使用“分组 + 实体 ID”。因此同一实例内部页面不会只因 URL 后缀改变就必然重新挂载最外层。
4. 浏览页的 `:projectType` 没有纳入最外层键，切换模组、资源包等类型时复用浏览组件，由内部 watcher 更新结果。收藏页虽同属浏览组，但拥有独立键。
5. 设置页使用固定的 `settings-shell` 键，而且显式禁用该页的 CSS 页面过渡。
6. 过渡层先按路由挂载，`Suspense` 位于其内部。动画开始不等待异步页面准备结束；数据完成也不会生成另一个过渡键。
7. 进入使用 180ms `ease` 透明度变化，离开使用 120ms `ease`；离开层禁用指针事件。模板未指定 `mode="out-in"`，不能把它理解成必须等待旧页消失才创建新页。
8. 最外层过渡节点在同一个 grid 区域叠放。其样式明确不做整页位移，以免 sticky 工具栏与滚动容器的包含关系改变。
9. 页面过渡受功能开关控制，CSS 也受系统 `prefers-reduced-motion` 条件控制。

**目标效果**：窗口外框、页头、侧栏、背景和工具栏锚点保持稳定，换的是页面内容的呈现；搜索参数和设置分类变化不会反复让整页闪现或滑入。

需要区分：同一全局样式文件还存在通用的 `.slide-*`，使用纵向 30px 位移与透明度。它不是最外层路由实际使用的 `.page-slide-*`；按名称猜测会读错实现路径。

### 3.2 加载调度：先绘制过渡，再处理较重的首批搜索

证据：[page-transition.ts](https://github.com/Mystic-Stars/Axolotl/blob/cf17974612cd6dcab139416e0bc5fbea252ce499/apps/app-frontend/src/helpers/page-transition.ts)、[Browse.vue:2355](https://github.com/Mystic-Stars/Axolotl/blob/cf17974612cd6dcab139416e0bc5fbea252ce499/apps/app-frontend/src/pages/Browse.vue#L2355)、App.vue:1918–1994。

源码事实：

- 路由与异步页面分别持有 loading token，`beforeEach`、`afterEach`、`Suspense pending/resolve` 各自开始或结束对应 token，避免把加载指示完全绑在一个动画回调上。
- 浏览页先等待首批必要依赖 `Promise.allSettled`；检查组件是否已经卸载；再调用过渡结束调度助手。
- 助手先等待 200ms，再优先使用 `requestIdleCallback`，并给出 500ms 超时；不支持该 API 时再等 32ms。这里的 500ms 是等待空闲回调的超时，不是额外固定动画时长。
- 延迟任务执行前再次检查组件是否卸载，再恢复返回页码并发起搜索。

**算法意义**：避免初次列表构建或解析与页面首帧争抢执行时间。不能据此声称动画一定运行在 GPU 或一定达到某个帧率；那需要实际测量。

### 3.3 侧栏：胶囊前后边缘分开运动

证据：[NavRail.vue](https://github.com/Mystic-Stars/Axolotl/blob/cf17974612cd6dcab139416e0bc5fbea252ce499/apps/app-frontend/src/components/ui/NavRail.vue)。

源码事实与执行顺序：

1. 导航项及其图标/文字留在原位。独立胶囊绝对定位在容器中，导航文字位于它上方；选中项自身的背景设为透明，避免同时显示两块选中底色。
2. 路由 path/query 变化后等待 `nextTick()`，再查询实际激活元素。
3. 若元素没有有效布局位置或容器高度为零，隐藏胶囊，不从无效坐标启动动画。
4. 测量目标上边距、下边距、左边距、宽度。其中目标下边距为 `容器高 - 目标上边距 - 目标高`。
5. 向下移动时：下边缘立即运动，上边缘延迟 120ms；向上移动时相反。每条边运动 150ms，曲线为 `cubic-bezier(0.4, 0, 0.2, 1)`。
6. 左位置与宽度同样有 150ms 过渡。两条纵向边错时更新，所以中间态会变长，再收回到目标行的高度。单次纵向移动的收尾约在 270ms，而不是单纯 150ms。
7. 首次测量直接放到正确位置，下一帧才启用过渡，防止首次出现时从原点飞过来。

**目标效果**：选中胶囊像柔软材质在导航项间流动，文字、图标、正文都不被推走。当前 Onion 的 3px 竖线移动不是该效果的等价实现。

插值描述：对每条边独立计算 `v(t)=v0+(v1-v0)*E(clamp((t-delay)/duration,0,1))`。CSS 贝塞尔曲线的 `E` 需按横坐标反求参数，不能直接把时间当作贝塞尔曲线参数代入纵坐标。

### 3.4 页内标签：同样是胶囊，但多了布局校准与短期状态恢复

证据：[NavTabs.vue:239](https://github.com/Mystic-Stars/Axolotl/blob/cf17974612cd6dcab139416e0bc5fbea252ce499/packages/ui/src/components/base/NavTabs.vue#L239)。

源码事实：

- 根据路由匹配或本地 activeIndex 计算当前标签，测量四条边的位置。
- 左/右、上/下边缘按移动方向设置先后顺序；尾缘延迟是 200ms，边缘过渡仍为 150ms，形成与侧栏类似但参数不同的流动。
- 初次定位直接设置终态。
- `ResizeObserver` 不直接开新动画，而是在下一帧重新测量；只有矩形真的变化才直接校准位置。布局变化不冒充用户切换。
- 按导航组保存的是滑块几何状态，不是屏幕截图；快照有效期为 1000ms，用来避免组件短期重挂载时滑块回原点再跳过去。
- 监听器、观察器和恢复记录具有明确清理路径。

**不能混淆**：这里的 slider snapshot 是几个数字，与 Onion 第一版抓取整页像素覆盖淡出的方案完全不同。

### 3.5 按钮与开关：只在局部可视层变化

证据：[ButtonFrame.vue:13](https://github.com/Mystic-Stars/Axolotl/blob/cf17974612cd6dcab139416e0bc5fbea252ce499/packages/ui/src/components/base/buttons/ButtonFrame.vue#L13)、[defaults.scss:68](https://github.com/Mystic-Stars/Axolotl/blob/cf17974612cd6dcab139416e0bc5fbea252ce499/packages/assets/styles/defaults.scss#L68)、[Toggle.vue](https://github.com/Mystic-Stars/Axolotl/blob/cf17974612cd6dcab139416e0bc5fbea252ce499/packages/ui/src/components/base/Toggle.vue)。

| 对象 | 源码实际变化 | 时长与边界 | 预期感受 |
| --- | --- | --- | --- |
| 新按钮 ButtonFrame | 背景、文字、阴影、filter、opacity、transform | 150ms ease-out；有效按下缩放到 0.97 | 按钮轻微下压，周围布局不让位 |
| 旧 `.button-animation` | 按下缩放到 0.95；filter 等分属性过渡 | transform 50ms、filter 200ms、opacity 500ms，曲线各自定义 | 这是另一路旧组件样式，不能把这些参数当成所有按钮统一规则 |
| 普通开关 | 滑块横向移动 24px；容器颜色变化 | 200ms；点击立即更新模型 | 滑块明确从一端滑向另一端 |
| 小开关 | 滑块横向移动 20px | 200ms | 同类效果，尺寸不同 |
| 开关 hover/active | 普通滑块 16px，hover 到 18px，active 到 14px，配合正负 margin 居中 | 200ms；禁用时不做这些交互 | 轻微膨胀/压缩，而不是整行移动 |
| 复选框 | 勾选符与局部颜色改变，按下局部 scale-95 | 更新布尔模型，禁用时不响应 | 状态直接反馈，不触发列表过渡 |

CSS transform 改变的是呈现，不要求重新计算相邻按钮的布局。Qt 如果改变布局管理的实际 widget geometry，不能视为等价移植。

### 3.6 折叠区域：明确分开准备、运动、完成

证据：[Collapsible.vue](https://github.com/Mystic-Stars/Axolotl/blob/cf17974612cd6dcab139416e0bc5fbea252ce499/packages/ui/src/components/base/Collapsible.vue)。

打开流程：取消 `display:none` → 等 `nextTick` → 下一绘制帧修改打开状态 → 网格行从 0fr 过渡到 1fr → 收到属于自身的 transitionend 后标记 fullyOpen。

关闭流程：先取消 overflow-visible、准备裁切 → 等布局和下一帧 → 1fr 过渡到 0fr → transitionend 后设置 `display:none`。

时长 300ms ease-in-out；首次挂载下一帧才启用动画；减少动态效果时取消过渡；关闭内容通过 `inert` 避免隐藏控件仍进入键盘交互。

关键点：在布局准备完成前启动插值、在收起开始时直接 hide，都无法得到同样效果。

### 3.7 弹层：有阶段、代次与资源清理

证据：[NewModal.vue:231](https://github.com/Mystic-Stars/Axolotl/blob/cf17974612cd6dcab139416e0bc5fbea252ce499/packages/ui/src/components/modal/NewModal.vue#L231)。

源码使用 `closed/opening/open/closing/disposed` 五种阶段，以及递增的 transitionGeneration。

- show 前取消旧计时器，增加代次，建立弹层栈、锁滚动、记录并管理焦点；50ms 准备后进入可见状态。
- hide 同样取消旧计时器、增加代次，进入 closing，恢复焦点与滚动；300ms 收尾后，只有代次和阶段仍匹配才最终卸载并触发 afterHide。
- 快速开关时，旧定时回调不能回写新弹层状态。
- unmount 标记 disposed、取消计时器并移除监听。

本项目仍应遵守用户要求优先内嵌子界面；不应为了借鉴动效重新引入独立登录或安装窗口。

### 3.8 列表与搜索：平滑先来自稳定身份与有限工作量

证据：[ContentCardTable.vue:98](https://github.com/Mystic-Stars/Axolotl/blob/cf17974612cd6dcab139416e0bc5fbea252ce499/packages/ui/src/layouts/shared/content-tab/components/ContentCardTable.vue#L98)、[virtual-scroll.ts:137](https://github.com/Mystic-Stars/Axolotl/blob/cf17974612cd6dcab139416e0bc5fbea252ce499/packages/ui/src/composables/virtual-scroll.ts#L137)、[use-browse-search.ts:214](https://github.com/Mystic-Stars/Axolotl/blob/cf17974612cd6dcab139416e0bc5fbea252ce499/packages/ui/src/layouts/shared/browse-tab/composables/use-browse-search.ts#L214)。

列表：

- 行以稳定的 item.id 为 key，选择集合与正在变更的 ID 集合单独维护。
- 表格把行高设为 74px，缓冲 5 行，初始最多取 20 行；虚拟滚动只渲染可见区附近的条目。
- 令条目总数为 N、行高 h、相对滚动位置 s、视口高 H、缓冲 b，则可见区从 `floor(s/h)` 开始估算，窗口容量为 `ceil(H/h)+2b`；起始位置夹在合法范围内，上方占位高度为“窗口起始行 × h”。
- 滚动监听为 passive，容器尺寸通过观察器同步，销毁时清理监听。
- 搜索、排序、筛选、滚动位置和锚点有各自状态，不依赖“销毁页面再重建”维持一致性。

搜索：

1. 条件变化立即增加 searchVersion、取消旧 AbortController、清除旧防抖计时器。
2. 200ms 防抖后启动新请求，创建新 controller 和新的版本号。
3. loading/error 是结果区状态；返回内容只有版本号仍匹配时才能更新。
4. 旧请求取消或过期，不覆盖当前结果、加载状态或错误。
5. 离开组件时增加版本号、取消防抖和请求。
6. 从详情返回浏览页时，等待结果加载完成、`nextTick` 和一帧后恢复 scrollTop。

这套流程避免旧结果闪回、视口重置和列表全量重建。不是给每行加淡入动画。

### 4.2 对第一版闪屏的证据边界

用户已经报告第一版整屏闪烁；其截图覆盖方案已在当前基线中移除。旧方案会抓取页面像素并叠在新页面上，连续导航还可能把进行中的覆盖层包含进下一张图，缩放又会立即移除覆盖层。这些是源码可见的风险。

## 5. 下一阶段实现路径（尚未执行）

### 阶段 0：先清除错误架构

- 删除通用 `@animate_change` 的整页位移和相应中断归位逻辑，不保留两套竞争的页面动画路径。
- 页面显示、历史返回、异步加载、设置草稿继续使用现有业务逻辑，不因动效引入另一套业务状态。
- 先建立“正文坐标与视口保持稳定”的回归基线。

### 阶段 1：稳定控件身份与更新边界

- 根页面 / 同一实例子页 / 同一浏览类别组 / 设置分类 / 参数变化 / 数据结果 / 用户选择，各自定义变化类型。
- 相同页面不触发新动作；同一导航组不销毁全部按钮。
- 列表用稳定 ID 和局部更新；保留勾选、滚动位置、搜索条件和焦点。数据确需刷新时独立处理失效。

### 阶段 2：先做一个导航胶囊原型

- 胶囊作为侧栏的背景绘制层；图标、文字和点击区域不移动。
- 使用四条边的浮点状态；按方向给尾缘延迟，匹配参考的 150ms 曲线与 120ms 错时，首次出现直接定位。
- Qt 可用统一时间线配合 `QEasingCurve` 或独立属性插值，绘制在稳定容器中；不通过 QLayout 管理条目的几何移动实现。
- 连续导航从当前可见边缘状态接续到新目标；不要先跳到旧目标，也不要先回原点。
- 布局重算只校准，不播放“路由切换”动画。

### 阶段 3：局部控件与折叠

- 按钮固定命中矩形和布局尺寸，只在绘制层做轻微缩放及颜色/阴影过渡；不移动整行。
- 开关按模型状态即刻提交，视觉状态从当前滑块位置续接，增加参考中的局部尺寸变化。
- 折叠先准备可见性与裁切，再开始高度插值，完成后决定隐藏和键盘可达性。
- 只保留一套时长、曲线和减少动态效果策略，避免 QSS 状态切换与自绘效果互相覆盖。

### 阶段 4：最后评估页面内容过渡

- 明确目标是与参考一致的“稳定外壳 + 内容过渡”，不是再试整页晃动。
- 设置页、同组子页和筛选变化排除整页过渡。
- Qt Widgets 与 Web 合成机制不同，不能宣称把 opacity 数值抄过来就等价。先在临时原型验证背景保持恒定、滚动不跳、工具栏锚点不变、文字不重影和无亮度脉冲。
- 原型达不到目标就保留稳定切页和已验证的局部动效，不把未验收的全局实现并入主界面。

## 6. 验收标准

| 场景 | 必须观察和测量的结果 |
| --- | --- |
| 重复点击当前导航项 | 不启动正文动画，不重建侧栏，焦点和滚动位置保持 |
| 改筛选、勾选模组 | 只更新对应状态/结果，页头、工具栏、窗口背景和正文原点不移动 |
| 侧栏切换 | 图标文字几何不变；胶囊前后边有连续中间态；到终点时无纠正跳跃 |
| 快速反向切换 | 从当前视觉状态反向，不先去旧目标；没有陈旧回调覆盖新状态 |
| 初次进入与窗口 resize | 正确测量后直接定位，不从默认坐标滑入或补跳 |
| 动效中输入/滚轮 | 输入立即处理，不额外造成正文位移或整屏明暗变化 |
| 按钮按下/释放 | 布局及点击区域不变，视觉压缩/回弹连续；禁用项无响应 |
| 开关快速反复点击 | 业务状态正确，滑块从当前位置续接；不触发列表重建 |
| 异步响应倒序 | 旧请求不能覆盖最新结果、错误或 loading 状态 |
| 返回详情来源页 | 分类、筛选、页码、选中项和滚动锚点恢复，不回顶后再闪回 |
| 减少动态效果 | 控件直接终态，未决动画、计时器和观察器按规则清理 |
| 实际显示检查 | 在真实刷新率、100%/125%/150% DPI 下观察；离屏状态测试不能代替呈现检查 |
| 帧时序 | 记录连续帧的状态、呈现间隔、最慢帧与重复帧；以设备刷新周期评估，不能用手动 setCurrentTime 冒充帧率测试 |
| 亮度与构图 | 在布局稳定的区域取样检查是否出现全屏黑/白帧或亮度脉冲；读数只用于回归检查，不宣称医学安全结论 |

测试必须验证需求。当前“页面确实平移了 18px”的断言应当被替换，不能继续作为验收依据。
